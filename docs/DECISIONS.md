# Решения и их причины

## Java внутри контейнеров, а не на хосте
На хост Java не ставится. Каждый сервер запускается в образе `eclipse-temurin:<8|17|21|25>-jre`, а версия хранится в настройках сервера.
- Переключение Java — это смена тега образа: без `update-alternatives` и без конфликтов между версиями.
- Рекомендуемая версия берётся из метаданных:
  - Mojang (`javaVersion.majorVersion`);
  - PaperMC Fill v3 (`java.version.minimum`) — для Velocity 4.3 это 25.
- Если API недоступны, версия угадывается по номеру версии игры.

## Перезапуском управляет панель, а не Docker
У контейнеров `RestartPolicy: no`. Панель сама:
- замечает выход процесса;
- перезапускает сервер через 5 секунд;
- после 3 падений за 10 минут останавливает попытки и шлёт уведомление (защита от бесконечных падений).

Docker `unless-stopped` так не умеет и мешал бы корректной остановке.

После перезагрузки VPS панель запускает серверы с `desired_state = running`. Если перезапускается только панель, контейнеры продолжают работать, и она к ним заново подключается (attach + хвост логов).

## Контейнер пересоздаётся при каждом старте
Данные лежат в bind-mount, сам контейнер одноразовый. Новые RAM, CPU, порт или Java применяются простым перезапуском, без отдельной логики «обновить контейнер».

## Внутренний порт фиксирован
Внутри контейнера сервер всегда слушает 25565 (прокси — 25577), а Docker отображает на него выбранный порт хоста. Поэтому не нужно править `velocity.toml` или `config.yml` прокси до первого запуска, а смена порта не трогает конфиги.

## RCON для служебных запросов
Список игроков и TPS панель берёт по RCON. RCON-порт не публикуется наружу, панель ходит на IP контейнера во внутренней сети. Если слать `list` и `tps` в stdin, консоль засорялась бы. Строки самого RCON-клиента («RCON Client started…») из консоли панели скрываются.

## Память: heap меньше лимита контейнера
`-Xmx = RAM − max(512 МБ, 20%)`. При 85% heap сервер с `AlwaysPreTouch` упирался в лимит cgroup, и его убивал OOM-killer: метаспейс, code cache и direct buffers живут вне heap.

## Квота диска — программная
На одном ext4-разделе без project quota честных квот нет. Поэтому:
- панель считает размер папки (`du`);
- не даёт запустить сервер и загружать файлы сверх лимита;
- присылает уведомление.

Узкое место: процесс игры сам может записать больше лимита, пока работает (например, сгенерировать мир). Это будет видно в мониторинге, а при следующем старте сработает блокировка.

## Docker и ufw
Docker публикует порты в обход ufw. Это допустимо, потому что публикуются только игровые порты из уже открытого диапазона. MariaDB публикуется только на `127.0.0.1`. Docker настроен с `icc: false`, у каждого сервера своя bridge-сеть.

## Одна MariaDB на все серверы
Отдельный контейнер на каждую базу съел бы RAM 8-гигабайтного VPS. Поэтому общий `mariadb:11.4` (лимит 512 МБ) запускается лениво — при создании первой базы.
- У каждой базы свой пользователь с правами только на неё.
- Серверы с базами подключаются к сети `mcp-db` и видят хост `mcp-mariadb`.

## SQLite через `node:sqlite`
Нативных модулей сборки нет, бэкап — одна команда `sqlite3 .backup`. Для одного VPS PostgreSQL избыточен.

## CSRF
Сессия хранится в cookie с `SameSite=Strict`. Кроме того, каждый изменяющий запрос с cookie обязан нести заголовок `X-Requested-With: mc-panel`: чужой сайт не может его добавить без CORS-preflight, а CORS мы не разрешаем. Токены не нужны. Запросы с API-ключом (Bearer) этой проверки не требуют.

## Симлинки внутри папки сервера
Код плагинов выполняется в контейнере и может создать симлинк, например `server.properties → /etc/mc-panel/.env`. Защита:
- при чтении через файловый менеджер проверяется `realpath`;
- файлы, которые панель пишет сама, открываются с `O_NOFOLLOW` (подложенная ссылка заменяется обычным файлом);
- временные файлы создаются с `O_EXCL`;
- при удалении и переименовании проверяются реальные пути родительских папок.

## Самообновление без root
Панель работает от `mcpanel` с `NoNewPrivileges`, поэтому `sudo` ей недоступен. Кнопка «Обновить» создаёт файл-флаг, а root-юнит `mc-panel-update.path` замечает его и запускает `update.sh`.

## Сеть до Cloudflare
С этого VPS первый SYN до части CDN периодически теряется. Встроенный в Node Happy Eyeballs даёт каждому адресу ~250 мс, и `fetch` падал с `ETIMEDOUT`, хотя `curl` работал. Решение:
- `setDefaultAutoSelectFamilyAttemptTimeout(3000)`;
- два повтора с паузой для всех запросов к внешним API и скачиваний;
- сверка контрольных сумм (sha1 у Mojang, sha256 у PaperMC, sha512 у Modrinth).

## i18n
Словари `web/src/lib/locales/{ru,en}.ts` покрывают каркас: навигацию, статусы, действия, вкладки и общие кнопки. Тексты отдельных страниц пока на русском прямо в разметке и переносятся в словари постепенно; переключатель языка уже есть в меню пользователя.
